# 部署到远程测试环境

前提：改动已经按 `AGENTS.md` 的流程**测试通过并提交**。测试没过，不要执行这个 skill。

## 步骤

1. **确认没有遗漏**
   - `git status --short`：有没有该提交却没提交的文件？有没有不该提交的文件（`.env`、`*.db`）？
   - `.venv/bin/python scripts/changes.py run`：如果上次运行测试之后又改过代码，就再运行一次。
   - `python3 scripts/changes.py scope`：确认这个 PR 只改了一个项目，或者只改了平台。

2. **push 到自己的分支并开 PR**（不要直接 push 到 `main`）
   ```bash
   git push -u origin <当前分支>
   ```
   然后用 GitHub 工具开 PR 到 `main`（已有 PR 就不用再开，push 后 PR 会自动更新）。标题和描述用英文。
   **不要问负责人要不要开 PR**：负责人已明确授权，测试通过就直接开（见 `AGENTS.md` 开发流程第 3 步）。开完后订阅 PR 动态，继续下一步。
   - 负责人本人账号开的 PR：会自动 approve，CI 测试通过后自动合并。
   - 别人的 PR：要等负责人审核。告诉用户 PR 链接，请他去审核。

3. **等待合并和上线**（先等合并，再轮询 `/version`，总共最长 10 分钟）
   ```bash
   scripts/wait_for_deploy.sh
   ```
   这个命令可能要运行几分钟，Bash 的超时时间要设到 600000 毫秒左右。
   - 退出码 `0`：已上线。
   - 退出码 `1`：超时。如果卡在「等待合并」，去 GitHub 看 PR：CI 是否失败（失败就修好再 push）、是否在等审核。如果卡在部署，告诉用户去 Render Dashboard 的 **Events / Logs** 页面看部署是否失败，并请用户把报错发过来。**不要说已经上线。**
   - 退出码 `2`：参数或环境错误，按提示处理。
   - CI 失败时自己修，但同一个 PR **最多修 3 轮**；PR 被打上 `needs-human` 标签后立刻停手，告诉负责人卡在哪（见 `AGENTS.md` 开发流程第 4 步）。
   - 如果输出 `⚠️ 线上没有使用 PostgreSQL`，立即告诉用户检查 Render 上的 `DATABASE_URL`。

4. **通知用户**（用中文）
   - 新版本已上线，可以刷新页面了（前端文件带版本号，普通刷新就行）。
   - 这次改了什么，用一两句话说明，并告诉用户可以怎么试。
   - **列出可以直接点开的完整链接**：把 `wait_for_deploy.sh` 输出的「🔗 链接」（项目页面、网站首页、PR）原样贴进最后一条回复。
   - 游戏世界会在部署前自动存档、部署后恢复，正常情况下不会丢进度。如果这次改了存档格式（`Game.SAVE_VERSION` 变了），要提醒用户：这次部署会开一个新世界。
