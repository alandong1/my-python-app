# 记账本 · 需求与设计决定

状态标记：✅ 已实现　📋 待办　❌ 已放弃

## 1. 目标

- ✅ 一个网页版的记账本：按月记收入和支出，能看到本月合计和结余。
- ✅ **截图识别金额**：在页面上快速双击，截图并识别其中的数字，用户挑一个填进金额。
- ✅ 需要登录（平台账号，含游客）。每个人的账目只有自己能看到、能删除。

## 2. 功能

### 2.1 记账
- ✅ 类型：支出 / 收入。分类：
  - 支出：餐饮、交通、购物、居住、娱乐、医疗、学习、其他
  - 收入：工资、奖金、理财、其他
- ✅ 金额：元，最多两位小数，范围 0.01 ~ 1,000,000。
- ✅ 日期：默认今天，不能是未来（允许明天，时区差别），不早于 2000 年。
- ✅ 备注：可不填，最多 100 字。
- ✅ 删除：只能删自己的账目。
- ✅ 切换月份，查看该月账目、支出合计、收入合计、结余。

### 2.2 截图识别（核心）
- ✅ **快速双击**页面空白处触发（点在按钮、输入框、弹窗上不算）；页面上也有「📷 截图识别金额」按钮。
- ✅ 截图方式按设备分两种（判断在 `canShareScreen()`）：
  - **电脑浏览器**（不是触屏，并且浏览器支持 `getDisplayMedia`）：屏幕共享，浏览器弹出「选择要共享的屏幕或窗口」，抓一帧画面，用完立刻停止共享。
  - **手机 / 平板（触屏）**：网页**没法**直接截整个手机屏幕（浏览器不允许，也没有可靠的接口）。所以双击后打开相册，选刚才用电源键+音量键截的图。
  - 原因：手机浏览器对屏幕共享的支持不一致，不能只看接口在不在，所以触屏设备一律走相册。
- ✅ 识别：截图在浏览器里用 Tesseract.js 识别文字，限定只认数字和 `.`、`,`，减少误认。
- ✅ 结果：服务器从识别文字里找出所有可能的金额（`POST /api/parse-numbers`），列成按钮，**用户点选**后填进金额。
- ✅ 截图记账的账目带 📷 标记（`source = screenshot`）。
- ✅ 图片最长边超过 2000 像素会先缩小，加快识别。

### 2.3 为什么不自动决定金额
- 屏幕上的数字很多（时间、订单号、余额、手机号……），自动猜错的代价（记错钱）比多点一下大。
- 所以识别后只给候选，由用户选。以后如果要自动识别，可以加「金额大概在哪一行」的规则，但要先看实际截图的效果。

## 3. 技术选型

| 部分 | 选择 | 为什么 |
|---|---|---|
| 后端 | FastAPI（平台已用） | 和平台其他部分一致；账户、数据库直接复用。 |
| 数据库 | 平台的 PostgreSQL / SQLite，表名 `bookkeeping_entries` | 账目需要跨设备保存、按用户隔离，必须放服务器。 |
| 前端 | 原生 HTML / CSS / JavaScript | 页面很简单，不需要框架；没有构建步骤，部署后直接可用。 |
| 文字识别 | **Tesseract.js 5.1.1**（浏览器里运行，从 jsDelivr CDN 加载） | Tesseract 是开源的 OCR 引擎，Tesseract.js 是它的 JavaScript 版，可以在浏览器里直接识别图片，不需要把截图上传到服务器（隐私更好，也不占服务器资源）。第一次使用要下载识别数据（几 MB），之后浏览器会缓存。 |
| 金额存储 | 整数「分」（`amount_cents`） | 小数用浮点数相加会有误差（0.1 + 0.2 ≠ 0.3）；整数相加永远精确。 |

- 依赖：没有新增 Python 依赖。Tesseract.js 通过 CDN 加载，版本号已固定。
- 换技术的时机：如果识别准确率不够（比如手机截图里的小字总认错），可以考虑换成云端 OCR 服务（需要 API 密钥，属于 🖐️ 需要负责人去外部注册的情况），或者用更大的识别模型。

## 4. 已知限制

- 📋 **手机上不能「双击直接截屏」**：这是浏览器的限制，网页不能在后台悄悄截取整个手机屏幕。现在的做法是双击后打开相册，手动选截图。如果要真正的「一键截屏」，只能靠系统快捷方式（例如 iPhone 的「轻点背面」+ 快捷指令），那不在网页里完成。
- 📋 电脑上快速双击会弹出屏幕共享的选择框；如果误触会有点烦，后面可以加一个开关。
- 📋 识别的是屏幕上的数字，不理解「哪个是金额」。实际截图效果要看了再调（比如只识别某一块区域）。
- 📋 页面文字目前只有中文，没有英文翻译（平台的中英切换暂未接入）。
