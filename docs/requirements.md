记录「做什么」和「为什么这样做」。需求有变化时**先改需求文档，再改代码**（见 `AGENTS.md`）。
这里记录**平台层面**的需求；每个项目自己的需求在 `projects/<slug>/REQUIREMENTS.md`。

- 状态标记：✅ 已实现　🔒 已实现但未启用　🚧 进行中　📋 待办　❌ 已放弃

## 1. 平台定位

- ✅ **Dev Lab** 是负责人的个人项目平台：以后的游戏、工具、AI agent 等项目都在这里开发和测试。
- ✅ **一个仓库、一个网站、一个数据库、一套开发流程**（`AGENTS.md`）。
  - 原因：负责人希望所有项目共用同一套流程和基础设施，不必每个项目重新搭部署、数据库和登录。
- ✅ 首页 `/` 是「**应用商店**」：卡片列出所有项目（图标、名字、分类、状态、简介），点击进入。
- ✅ 每个项目挂在 **`/apps/<slug>/`** 下。
  - 原因：路径规律统一，不会和平台自己的 `/api`、`/static` 冲突。
- ✅ **未登录也能浏览商店**；进入需要登录的项目时再弹出登录（含游客一键进入），登录后自动进入项目。
- ✅ 项目之间相互隔离：网址、数据库表名（`<slug>_` 前缀）、代码都分开，规则见 `AGENTS.md`「项目之间的边界」。
- ✅ 太重的项目可以单独部署，在商店里用 `external_url` 登记。
  - 原因：所有项目在同一个进程里运行，Render 免费版内存有限；一个项目太耗资源会拖垮整个网站。

## 3. 账户与登录

- ✅ **游客登录**：浏览器第一次访问时在 localStorage 里生成一串随机凭证，作为游客身份。同一个浏览器再来还是同一个人。
  - 限制：换浏览器、换设备、清除浏览器数据后无法找回。登录页面上有提示。
- ✅ **用户名 + 密码**注册和登录。用户名 3–20 个字符（可以用中文，不区分大小写），密码至少 8 位。
- ✅ **可选绑定邮箱**：需要点击验证邮件里的链接才算绑定成功。绑定后也可以用邮箱登录。
  - 🔒 发邮件需要配置 SMTP。没有配置时，验证链接打印在服务器日志里。
- 🔒 **第三方登录：Google、Apple、微信**。代码已完成，并用模拟数据测试过；**配置了对应的密钥才会启用**，目前三个都没有配置。
  - Google：免费，可以随时申请。
  - Apple：需要 Apple Developer Program（每年 99 美元）。
  - 微信：需要企业认证的微信开放平台账号，个人开发者基本无法申请。
  - 已登录的用户（包括游客）可以在「我的账号」里绑定第三方账号；游客绑定后变成正式账号。
- ✅ **账号全平台通用**：在 Dev Lab 登录一次，所有项目都认得同一个人。登录页面在首页，项目页面没登录时跳到首页登录，登录后再跳回来。

**安全方面的决定**
- 密码用 bcrypt 哈希存储；登录会话放在 **HttpOnly cookie** 里，数据库只存会话 token 的哈希。
  - 原因：数据库泄露或网页被注入恶意脚本时，都拿不到能直接登录的凭证。
- 登录、注册有频率限制；WebSocket 拒绝来自其他网站的连接；OAuth 使用 state 参数防止伪造登录。


## 4. 环境与部署

- ✅ **远程测试环境**：Render（网址见 `deploy.conf`）+ Neon PostgreSQL（us-east-2）。目前没有真实用户。
- ✅ 开发流程：本地测试 → **直接 push 到 `main`** → Render 自动部署 → 通知负责人刷新。
  - 原因：个人项目、快速迭代，先不走 PR。
- ✅ 账户和登录会话保存在数据库里。
- ✅ Render 上没有配置 `DATABASE_URL` 时，服务**拒绝启动**。
  - 原因：曾经因为漏配这个变量，服务悄悄用了临时 SQLite 文件，重启后账号全部丢失（2026-11-22）。
- ✅ 开发规范写在 `AGENTS.md`，Claude Code、Codex、Copilot 等 AI 工具共用同一份。

- ✅ 通用的**快照存档服务**（表 `world_snapshots`，按项目 slug 区分），项目可以直接用来保存自己的状态。

## 5. 待办与想法

按大致优先级排列，负责人可以随时调整。

- 📋 **页面自动更新**：发现服务器版本变了，自动刷新或提示刷新。
- 📋 **配置 Google 登录**：需要负责人先在 Google Cloud Console 申请 OAuth Client。
- 📋 **找回密码**：通过已绑定的邮箱重置密码（需要先配置 SMTP）。
- 📋 **游客升级为正式账号**：游客直接设置用户名和密码（目前只能通过绑定第三方账号升级）。
- 📋 **正式环境**：有真实用户之后，拆分为 `production` 分支 + 第二个 Render 服务 + Neon 数据库分支。
- 📋 **数据库迁移工具（Alembic）**：等需要修改已有的表时再引入。
- 📋 Render 和 Neon 放到同一个区域，降低数据库延迟（Render 服务的区域在创建后不能更改，需要新建服务）。
